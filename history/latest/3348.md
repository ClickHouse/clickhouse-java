- **[client-v2, jdbc-v2, jdbc-v1]** Fixed Enum labels with a backslash escape in the type name, such as
  `Enum8('a\nb' = 1)`. The client dropped the backslash and kept the next character, so the label was read as `anb`
  instead of `a`, a newline and `b`, and writing the real label failed with `Unknown enum name`.
  `ClickHouseUtils.unescape` now decodes escapes the same way as the server does in a string literal. `\a`, `\b`,
  `\e`, `\f`, `\n`, `\r`, `\t`, `\v`, `\0` and `\xHH` become the matching character and `\N` is removed. A backslash
  before a backslash, a quote, a backtick, `/` or `=` is removed. A backslash before any other printable character is
  kept, so `\z` stays `\z` where it was `z` before. Strings without a backslash escape are read as before. jdbc-v1
  uses the same method for quoted file names and for a setting value that it reads from the server, and these now
  follow the same rules. (https://github.com/ClickHouse/clickhouse-java/issues/3348)
