- **[client-v2, jdbc-v2]** Fixed `Statement.cancel()` to not throw an `SQLException` when the statement has no running
  query (the query is finished or not started yet). Since ClickHouse 26.11, `kill_throw_if_noop` is enabled by default,
  and the server returns `NOTHING_TO_KILL` for the `KILL QUERY` that `cancel()` sends. `cancel()` now ignores this
  error. Other `KILL QUERY` errors (for example, an unknown `cluster_name`) are thrown as before. Added the
  `ServerException.NOTHING_TO_KILL` error code constant to `client-v2`.
  (https://github.com/ClickHouse/clickhouse-java/issues/3264)
