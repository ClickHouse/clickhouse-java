- **[jdbc-v2]** Fixed the RowBinary writer ignoring the INSERT column list. With
  `beta.row_binary_for_simple_insert=true`, `INSERT INTO t (b, a) VALUES (?, ?)` was writing
  values in table order instead of statement order, and column subsets like `INSERT INTO t (k, b)`
  on a wider table wrote into the wrong columns. The JavaCC parser now extracts the column list
  (the ANTLR4 backends already did), and `executeLargeUpdate()` passes the columns to the server.
  (https://github.com/ClickHouse/clickhouse-java/issues/3422)
