## Bug Fixes

- **[client-v2]** Reading a `Native` result that spans more than one block no longer loses rows at
  each block boundary. The last row of a block and the first row of the next were dropped and
  returned as two all-`null` rows, with the row count unchanged and no error. The reader reads one
  row ahead, and each new block re-published the schema, which replaced the row buffers while a
  row was still held in them. The buffers are now kept when the column count is unchanged.
  (https://github.com/ClickHouse/clickhouse-java/issues/3151)
