## Breaking changes

- **[jdbc-v2]** `ResultSet#getString(...)`, and `ResultSet#getObject(...)` when it returns a `String`, now cut a
  `FixedString(N)` value after its last valid UTF-8 character: the trailing zero bytes (`\0`) that the server adds to a
  value shorter than `N` bytes, and an incomplete multi-byte character at the end, are removed.
  `toFixedString('Dario', 10)` is read as `"Dario"`, not as `"Dario\0\0\0\0\0"`. Applications such as Tableau 2026.3
  show these zero bytes. Only top-level `FixedString` columns change. An application that removes the zero bytes itself
  (for example with `indexOf('\0')`), or that expects a text of `N` characters, must change. To read all `N` bytes, use
  `getBytes(...)`, `getBinaryStream(...)` or `getObject(..., byte[].class)`, which are not changed.
  (https://github.com/ClickHouse/clickhouse-java/issues/3288)
