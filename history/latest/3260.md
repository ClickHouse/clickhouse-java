- **[client-v2, jdbc-v2]** Fixed `Connection#getNetworkTimeout()`, which returned `0` (no limit) when the `socket_timeout`
  property was set and `setNetworkTimeout` was not called. A connection pool that saved this value and restored it
  after validation disabled the configured socket timeout. The client now exposes a runtime network timeout, and
  JDBC delegates `getNetworkTimeout()` and `setNetworkTimeout()` to it. Restoring the saved value therefore keeps
  the configured timeout and applies it to subsequent requests from existing as well as new statements.
  `setNetworkTimeout(executor, 0)` still disables the socket timeout. With a pool, the configured `socket_timeout`
  now applies after validation: a request that takes longer fails with a socket timeout, and the connection is
  closed because the pool set a network timeout.
  (https://github.com/ClickHouse/clickhouse-java/issues/3260)
