- **[client-v2, jdbc-v2]** Fixed a server error with an exception type other than `DB::Exception` (for example
  `Code: 279. DB::NetException: ...`, `Code: 999. Coordination::Exception: ...` or
  `Poco::Exception. Code: 1000, ...`) reported as `<Unreadable error message>`. The client looked for the text
  `<code>. DB::Exception:` in the response body to find the start of the message. It now looks for `Code: <code>`
  followed by `.` or `,`, which every server error message contains. For the `Poco::Exception`, `std::exception` and
  `Unknown exception` formats the message starts at `Code: <code>`, without the type label in front of it.
  The client now searches the whole response body, so the result does not depend on how the body is split between
  reads. With `client.use_http_compression` enabled, the client no longer drops the first 4 bytes of a response body
  that the server did not compress (for example the error message for an unknown setting).
  (https://github.com/ClickHouse/clickhouse-java/issues/2287)
