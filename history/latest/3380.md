- **[client-v2]** Fixed reading an `Array(Point)` or `Array(Array(Point))` column, and an `Array(Point)` inside a
  `Map`, `Tuple`, `Variant` or `Dynamic` value. The read failed with `IllegalArgumentException: array element type
  mismatch` and the whole row was lost, in `Client#queryAll`, in the binary readers and in jdbc-v2, where
  `ResultSet#next()` threw `SQLException`. A `Point` is read as a `double[]`, and the reader put the points into an
  `Object[][]`, which cannot hold a `double[]`. The points of a non-empty `Array(Point)` are now kept in an
  `Object[]`, the same as for an empty `Array(Point)` and for `Array(Nullable(Point))`. Each point is still a
  `double[]`. Other arrays keep the classes they had. The `Native` format reader does not decode the Native layout of
  an array of tuples, so it now reads an `Array(Point)` with more than one point in a block with wrong values, the
  same as `Array(Tuple(Float64, Float64))`, instead of throwing. That is the separate bug
  [#3156](https://github.com/ClickHouse/clickhouse-java/issues/3156).
  (https://github.com/ClickHouse/clickhouse-java/issues/3380)
