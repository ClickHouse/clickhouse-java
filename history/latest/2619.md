## Bug Fixes

- **[client-v2]** Binary serialization of integer columns no longer changes a value that does not fit the column type.
  A `Long`, `BigInteger`, `BigDecimal`, `double` or other `Number` value was narrowed without a check, so for example
  `2147483648L` was written as `-2147483648` into an `Int32` column, and an `Int128` or `Int256` column accepted a value
  up to the unsigned maximum and stored it as a negative number. A `BigDecimal` or `double` value outside the `long`
  range was written as a wrong value (for example `-1` for the `Int128` maximum) or rejected for `UInt64` and wider
  types although it was in range. Such values are now converted without loss of the integer part and checked against
  the range of the column type. A value that is out of range, `NaN` or an infinity is rejected with
  `IllegalArgumentException`; this includes a `double` or `float` at or above 2^63 for `Int64` (for example
  `(double) Long.MAX_VALUE`), which was clamped to the maximum before. A fractional part is still dropped. With the
  jdbc-v2 RowBinary writer (`beta.row_binary_for_simple_insert=true`), the insert fails with `SQLException`.
  (https://github.com/ClickHouse/clickhouse-java/issues/2619)
