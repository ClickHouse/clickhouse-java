## Bug Fixes

- **[client-v2]** The `Native` reader no longer returns rows that are not in the result after it loses its
  position in the stream. The reader does not decode the Native layout of some nested types, for example
  `Array(Array(Int8))` or `Map(String, Array(Nullable(Float64)))`, and reads a wrong number of bytes for them. It
  then read the bytes after that column as the header of a next block, for example a block with no columns and some
  rows, and returned the rows of that block. All blocks of a result have the same columns. The reader now compares
  each block with the first block and fails with `ClientException` if the columns are different. Such a read now
  fails; it does not return extra rows. Rows of the block with the wrong layout can still have wrong values.
- **[client-v2]** In the `Native` reader, `hasNext()` no longer changes the current row when it reads the next
  block: the getters return the values of the row that `next()` returned. The reader now creates the schema only
  from the first block.
- **[client-v2]** `NativeFormatReader.readRecord(Map)` no longer throws `NullPointerException` for an empty
  result, or `IndexOutOfBoundsException` for a block without rows. It now skips blocks without rows.
  (https://github.com/ClickHouse/clickhouse-java/issues/3365)
