- **[client-v2, jdbc-v2]** Logs no longer carry application data and no longer repeat. The client and the JDBC
  driver do not log SQL, bound values, credentials, query IDs, the client name and metadata, endpoint addresses (an
  endpoint quarantine names the host only) or exception messages at any level, `TRACE` included: the JDBC statement `TRACE` of the SQL, the SQL parser `DEBUG` of
  a statement that cannot be parsed, the `User-Agent` warning (now only its length) and the transport `DEBUG` of
  failed requests exposed them. A retried operation no longer logs a `WARN` per attempt and another before its
  exception is thrown: an operation that recovers logs one `WARN` with the retry count and the type of the last failure,
  and an endpoint quarantine and the all-endpoints-down fallback are each logged once. Exceptions that reach the
  application are not logged a second time, per-stream and per-statement `DEBUG` messages and per-object metadata
  messages are removed, and failures the client ignores are logged at `WARN` or `DEBUG` instead of `ERROR`. Public
  API, configuration, retries, metrics and spans are unchanged.
  (https://github.com/ClickHouse/clickhouse-java/issues/3295)
