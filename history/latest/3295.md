- **[client-v2, jdbc-v2]** Logs no longer carry SQL or bound values and no longer repeat. The JDBC driver does not
  log SQL statements or bound values at any level, `TRACE` included (the statement `TRACE` of the SQL is removed), the
  SQL parser does not log a statement that it cannot parse, and the `User-Agent` warning reports only the length of
  the value. Query IDs and the server address stay in the client logs, and a request without a query ID is logged
  as `unknown`; failures logged by the transport, the JDBC statement and the environment lookup carry the exception
  with its stack trace. A retried operation no longer logs a `WARN` per attempt and another before its exception is
  thrown: an operation that recovers logs one `WARN` with the retry count and the type of the last failure, and an
  endpoint quarantine and the all-endpoints-down fallback are each logged once. Per-stream and per-statement `DEBUG`
  messages and per-object metadata messages are removed, some diagnostic messages move to `TRACE`, and failures the
  client ignores are logged at `WARN` or `DEBUG` instead of `ERROR`. Public API, configuration, retries, metrics and
  spans are unchanged.
  (https://github.com/ClickHouse/clickhouse-java/issues/3295)
