- **[client-v2, jdbc-v1]** Fixed the width of a bare `Enum(...)` in a type name that the application writes, for
  example in a `TableSchema` for `Client#newBinaryFormatReader(response, schema)`, `RowBinaryFormatWriter` or
  `Client#register(Class, schema)`. `enum(...)` and `ENUM(...)` were always read and written as `Enum8`, so a value
  outside -128..127 used 1 of its 2 bytes and silently shifted the rest of the row. `Enum(...)` failed with
  `Unsupported data type: Enum`. Now a bare `Enum` is `Enum8` when all its values are in -128..127 and `Enum16`
  otherwise, the same as the server. The alias `ENUM` now belongs to `ClickHouseDataType.Enum`, not to `Enum8`, as
  in the server's `system.data_type_families`: `ClickHouseDataType.of("ENUM")` (in any letter case) returns `Enum`,
  and in jdbc-v1 the `ENUM` row of `DatabaseMetaData#getTypeInfo()` is now the same as the `Enum` row. Type names
  from the server (`RowBinaryWithNamesAndTypes`, `Native`, `Dynamic`) always spell `Enum8`/`Enum16` and are read as
  before. `BinaryStreamReader.EnumValue#getDataType()` returns the type of the value that was read (`Enum8` or
  `Enum16`). (https://github.com/ClickHouse/clickhouse-java/issues/3342)
