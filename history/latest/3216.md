- **[jdbc-v2]** Fixed `java.sql.Array#getResultSet()` and `getResultSet(long, int)` for an array from
  `Connection#createArrayOf` and for a geo value read with `ResultSet#getArray`. For a scalar element type such as
  `Int32`, `Nullable(String)` or `Date`, and for `Point`, `Ring`, `LineString`, `MultiPoint`, `Polygon`,
  `MultiLineString` and `MultiPolygon` values, they threw an unchecked `IndexOutOfBoundsException`. For a `Tuple` or
  `Map` element type, the `VALUE` column had the type of the first tuple field or of the map key, so `getObject(2)`
  failed. Now the `VALUE` column of an array from `createArrayOf` has the element type, the same as the `VALUE` column
  of an `Array(T)` value read from the server. The `VALUE` column of a geo value has the geo element type, the one
  that ClickHouse 26.10 returns for `x[1]`. `Ring`, `LineString` and `MultiPoint` have `Point` elements, `Polygon` has
  `Ring` elements, `MultiLineString` has `LineString` elements, `MultiPolygon` has `Polygon` elements, and a `Point`
  has `Float64` coordinates. `getBaseTypeName()` does not change. A `Tuple` or `Geometry` value read with `getArray`
  now reports its own type for the `VALUE` column, the same as `getBaseTypeName()`, and not the type of its first
  field or variant. An array from `createArrayOf` with a geo element type such as `Ring` holds whole `Ring` values, so
  its `VALUE` column is `Ring`, the same as for `Array(Ring)`.
  (https://github.com/ClickHouse/clickhouse-java/issues/3216)
